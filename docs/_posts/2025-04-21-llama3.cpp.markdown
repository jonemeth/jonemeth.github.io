[**llama3.cpp**](https://github.com/jonemeth/llama3.cpp) runs Meta's Llama 3 models
on the CPU using nothing but standard C++ and OpenMP. 

The project is a C++ port of [llama3.c](https://github.com/jameswdelancey/llama3.c)
by James Delancey, which in turn is derived from Andrej Karpathy's
[llama2.c](https://github.com/karpathy/llama2.c). I wanted to keep the code as easy to
follow as the original while using what modern C++ offers: classes for the layers,
standard algorithms instead of hand-written loops, and one executable that handles both
float32 and quantized models.

## Tested models

- Llama 3.1 8B and Llama 3.1 8B Instruct
- Llama 3.2 1B and Llama 3.2 1B Instruct
- Llama 3.2 3B and Llama 3.2 3B Instruct
- DeepSeek-R1-Distill-Llama-8B

## How the code is organised

Unlike the single-file C original, the code is split by responsibility:

| File | What it does |
|------|--------------|
| `Tensor.h/.cpp` | A tensor that can hold float32 and/or int8-quantized data |
| `layers.h/.cpp` | `RMSNorm`, `Linear`, `CausalAttention`, `FFN`, `TransformerBlock` |
| `Transformer.h/.cpp` | Token embedding, the stack of blocks, final norm and classifier |
| `Tokenizer.h/.cpp` | Llama 3 BPE tokenizer (encode / decode) |
| `Sampler.h/.cpp` | Temperature and top-p (nucleus) sampling |
| `main.cpp` | Checkpoint loading, generate and chat loops, CLI |
| `export.py` | Converts Meta or Hugging Face checkpoints to the llama3.cpp format |

Most functions map directly onto their counterparts in llama3.c, and I kept the
original comments where they still apply, so you can read the two side by side.

## One binary for float32 and int8 weights

In llama2.c and llama3.c, the float32 and the quantized paths live in separate programs.
In llama3.cpp they're the same program. The trick is the `Tensor` class, which keeps
up to two representations of its data and converts between them lazily:

```cpp
class Tensor
{
public:
    FloatTensor &f();                              // float view (invalidates int8)
    FloatTensor const &cf();                       // float view, keeps int8 valid
    QuantizedTensor &q(GroupSize groupSize);       // int8 view (invalidates float)
    QuantizedTensor const &cq(GroupSize groupSize);
    ...
private:
    bool isFloatValid_;
    bool isQuantizedValid_;
    FloatTensor floatTensor;
    QuantizedTensor quantizedTensor;  // int8 values + one scale per group
};
```

When you ask for the float view of a tensor that only holds quantized data, it gets
dequantized, and the other way round. 


## Building

The code is C++20 and tested on Linux. Build it with CMake or directly with g++:

```bash
git clone https://github.com/jonemeth/llama3.cpp
cd llama3.cpp
g++ -std=c++20 -Wall -Wextra -Werror -Ofast -fopenmp -march=native *.cpp -o llama3
```

The only third-party code is the header-only
[argparse](https://github.com/morrisfranken/argparse) library by Morris Franken, which
is included in the repository.

## Converting a model

Download a model from the [Llama repository](https://github.com/meta-llama/llama-models)
or from Hugging Face, for example:

```bash
git clone https://huggingface.co/meta-llama/Llama-3.2-1B
```

Then export it to float32:

```bash
mkdir models
python3 export.py ./models/Llama3.2-1B.bin --meta-llama <PATH-TO>/Llama3.2-1B/
```

or to int8 with `--quantize`:

```bash
python3 export.py ./models/Llama3.2-1B-q80.bin --meta-llama <PATH-TO>/Llama3.2-1B/ --quantize
```

For checkpoints downloaded from Hugging Face, use `--hf` instead of `--meta-llama`.
Converting the 8B model with quantization needed about 45 GB of memory (I used 16 GB of
RAM plus 48 GB of swap) and took around an hour and a half.

## Running

The same executable loads float32 and quantized checkpoints:

```bash
./llama3 ./models/Llama3.1-8B-q80.bin -i "The history of the C++ language"
```

For an interactive conversation, use an Instruct model in chat mode:

```bash
./llama3 ./models/Llama3.1-8B-Instruct-q80.bin -m chat
```

Chat mode builds the Llama 3 prompt format token by token (`<|begin_of_text|>`,
`<|start_header_id|>system<|end_header_id|>`, `<|eot_id|>` and so on), and accepts an
optional system prompt with `-y`.

Other options:

| Flag | Meaning | Default |
|------|---------|---------|
| `-t` | sampling temperature | 1.0 |
| `-p` | top-p for nucleus sampling | 0.9 |
| `-s` | random seed | current time |
| `-n` | number of tokens to generate (0 = unlimited) | 4096 |
| `-z` | path to the tokenizer | `tokenizer.bin` |
| `-d` | debug logging | off |

The program prints the achieved tokens per second at the end of a generation.

### DeepSeek-R1-Distill-Llama-8B

DeepSeek's R1 distillation onto Llama 3.1 8B uses the same architecture, so it exports
and runs like any other Llama checkpoint. The only difference is that its config
declares a context length of 131072 tokens, which would make the key/value cache
enormous. llama3.cpp caps the context at 2048 tokens when loading a model.
